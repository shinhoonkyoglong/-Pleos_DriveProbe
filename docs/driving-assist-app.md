# 일반 앱에서 주행 도움 사용하기

2026-11-12 후속 변경: [공식 파일 기반 확보](public-rest-stop-catalog.md)를 추가했다. 휴게소 215개와 졸음쉼터 253개를 포함하고 TBT에서 먼저 나오는 두 종류의 시설을 함께 고려한다. 명시적 방향 일치 또는 공식 양방향 시설은 즐겨찾기 없이 자동 연결하며, 방향이 모호하면 공식 목록에서 확인할 수 있다. 아래의 즐겨찾기 준비 절차는 보조 방식으로 남는다.

2026-11-12. 개발자 도구에 있던 준비 동작을 홈의 **주행 도움**으로 연결했다. 이 화면과 **휴게소 설정**은 Debug 전용이 아니며 Release에도 포함된다. 단계 시험·Replay·강제 차량 제어 버튼은 일반 사용 화면에 넣지 않는다.

## 사용자 흐름

1. 실제 차량 신호에서 **P·속도 0·화면 사용 가능** 상태를 확인한다. 알 수 없는 신호·모의 UX 제한으로 설정을 열지 않는다.
2. 홈 → **주행 도움 → 주행 도움 켜기**. 마이크 권한을 처음 허용하면 음성 준비를 이어서 시작한다. 마이크 FGS만 준비하며, 이 버튼 자체는 재생·녹음을 요청하지 않는다.
3. **공조·음성 도움 켜짐**을 확인한다. 음성 서비스가 준비되지 않았으면 홈과 주행 화면에 **음성 준비 필요**로 표시한다. 준비 알림을 누르면 앱으로 돌아올 수 있다.
4. **휴게소 설정**에서 현재 경로의 시설을 불러온다. 내비에 진행 방향의 휴게소를 실제 즐겨찾기로 저장해야 한다. 표시된 시설 중 하나를 직접 선택하고, 확인한 노선·방향과 체크를 저장한다. 기존 내비 경로는 변경하지 않는다.
5. 저장 후 현재 경로의 시설과 별도 탐색 ETA를 조회해 보여준다. 이 예상 시간은 현재 조회값이며, 실제 음성 제안 직전에 다시 조회·검증한다.
6. 실제 주행이 시작되면 기존 주행 화면으로 자동 전환한다. 생산 엔진의 유효한 판단에 따라 MILD 공조, CAUTION 음성 질문, DANGER 이름·ETA 제안과 명확한 동의 후 같은 휴게소 추가가 실행된다. DANGER가 추가한 경유지는 유지한다.
7. 정차 후 **주행 도움 끄기**로 자동 개입과 음성 준비를 중지한다. 이미 적용한 공조 설정·경유지는 자동 원복하지 않는다.

자동 도움 선택은 `driving_assist_settings.automaticEnabled`에 저장한다. 기존 기본값(자동 개입 ON)을 유지하되, 앱 프로세스를 새로 시작했다고 마이크 FGS를 자동 시작하지 않는다. 이전에 도움을 껐다면 앱을 다시 시작해도 꺼진 상태다. 진단 시험의 일시 중단·복구는 이 사용자 선택을 덮어쓰지 않는다.

## 연결과 상태 표시

- `DrivingAssistViewModel`: 준비·권한 응답·사용자 설정·실제 휴게소 조회/등록을 연결한다. 준비 버튼과 권한 결과 시점에 모두 정차·현재 작업 상태를 검사한다. 조회 중 설정 화면을 나가거나 정차 조건을 벗어나면 조회를 취소한다.
- `DrivingAssistScreen`, `RestStopSettingsScreen`: 기존 `KdTheme`의 큰 버튼·글자·색상과 기호를 사용한다. 일반 화면에는 실행 코드, 원본 TBT, 시험 추가·삭제 버튼을 표시하지 않는다.
- `InterventionModule`: 기존 생산 엔진 소비와 `DangerNavigationAction`을 그대로 사용한다. 앱 범위의 실행 소유권과 microphone FGS는 화면 이탈 후에도 유지된다. `MainActivity.onStop`의 수동 음성 시험 취소와 생산 작업을 구분한다.
- `voicePhase`: 실제 질문 재생·응답 대기·발화 인식·경유지 적용 확인 상태를 주행 화면에 전달한다. 동의 응답 뒤 SDK 적용을 기다리는 상태를 녹음 중으로 표시하지 않는다.
- 시설 설정은 `serviceAreaReview`와 토큰을 만들지 않는 `restNavigation.preview()`를 이용한다. 실제 SDK 인스턴스를 쓰며, 출발 전 화면의 debug 내비 예시 데이터는 사용하지 않는다. 등록 또는 미리보기만으로 경유지를 추가하지 않는다.
- 정차 설정은 실제 UX 제한과 신호를 요구한다. 주행 중 설정 버튼을 추가하지 않았으며, 주행 화면의 조작 없는 구조를 유지한다.

## 검증 범위

단위 테스트 514개(앱 321, departure-core 149, departure-ui 44), 앱·계측 APK 빌드와 Release Kotlin 컴파일을 통과했다. 새 테스트는 정차·알 수 없는 신호·모의 UX 제한 차단, 준비 상태 표시, 동의 이후 적용 확인 단계 전환을 포함한다.

`DrivingAssistAppTest`는 에뮬레이터의 실제 홈 버튼 → 주행 도움 진입 → 실제 microphone FGS 준비 → 휴게소 설정 진입과 실제 조회 → 도움 중지와 사용자 선택 저장 → 홈 상태 반영을 검사한다. 준비/중지 후에는 이전 자동 개입 선택·음성 준비 상태를 복구한다. 기존 사용자 DB와 경로를 지우지 않는다. 이 검사는 음성 녹음·발화 인식·경유지 쓰기·공조 변경을 실행하지 않는다.

나머지 선택 계측은 기존 DANGER 시험 진입, 인메모리 Room의 시험/실제 기록·전송 대기 분리, 실제 SDK TBT·즐겨찾기 조회를 확인한다. 전체 계측에는 기존 경로를 변경하는 시험이 있으므로 이 확인에는 선택한 클래스만 실행한다.

**남은 실제 효과 검증:** 현재 경로에는 휴게소 후보가 없어 DANGER 전체 실제 발화·추가·유지 시험은 별도로 준비해야 한다. 새 공조 전원/AUTO 정책을 포함한 전체 MILD의 실제 SDK 검증도 남아 있다. 일반 화면에 연결했다는 사실을 두 시험의 성공으로 간주하지 않는다. 실제 발화 절차는 [DANGER 통합 시험](danger-navigation-probe.md)을 참고한다.
