# 공식 파일 기반 휴게소·졸음쉼터 확보

2026-11-12 사용자 선택으로 공식 CSV를 앱에 포함하고, 추천 대상을 휴게소와 졸음쉼터 모두로 변경했다. 기존 즐겨찾기·최근 목적지 자동 일치 작업은 보조 경로로 유지한다.

## 동작

1. TBT의 휴게소(code 41 + 시설명)·졸음쉼터(code 99)를 **함께 수신 순서로** 확인한다. 다음 시설 앞에 종류 불명의 시설이 있으면 뒤 시설로 건너뛰지 않는다. 거리 숫자 최솟값이나 ETA 최솟값으로 다음 시설을 바꾸지 않는다.
2. 앱에 포함된 공식 시설 목록 468개(휴게소 215, 졸음쉼터 253)에서 종류·시설명·진행 방향을 비교한다. 인터넷·API 키·즐겨찾기 등록이 필요하지 않다.
3. TBT에 `용인휴게소(강릉방향)`, `용인졸음쉼터 강릉방면`처럼 방향이 명시되어 있으면 그 방향의 유일한 시설을 자동 확보한다. 공식 데이터가 `양방향`이고 해당 이름의 시설이 유일하면 방향 없는 TBT에서도 자동 확보한다.
4. **TBT에 방향이 없고 상·하행 후보가 구분되는 경우에는 임의로 선택하지 않는다.** 앱의 휴게소 설정에서 공식 파일의 후보 목록을 보여주며, 선택한 시설의 노선·방향을 채운 후 사람이 확인할 수 있다. 이 경우도 즐겨찾기 등록은 필요하지 않다. 이름이 유일하다는 사실만으로 누락된 반대편 시설이 없다고 가정하지 않는다.
5. 실제 SDK `requestTrip`으로 좌표까지의 ETA를 조회한다. 같은 생산 DANGER 실행 코드가 이름·ETA 제안 → 명확한 동의 → 경로·시설 재검사 → 실제 경유지 추가를 담당한다. 조회·시설 확인만으로 경로를 쓰지 않으며, 동의 후 추가한 시설을 자동 삭제하지 않는다.

공식 파일의 `용인(강릉)`은 표시 이름 `용인휴게소(강릉방향)`으로 정규화한다. 졸음쉼터 파일의 `인천기점 + 강릉종점`은 강릉 방향 표기로 읽는다. 임의 유사명·최근접 위치·현재 heading으로 방향을 추정하지 않는다. 같은 이름·방향 후보가 여러 개이면 자동 연결을 거부한다. 기준일이 미래이거나 366일을 넘으면 자동 사용하지 않는다.

## 식별자와 저장

- 공식 시설 ID는 `PUBLIC_CATALOG:종류:노선번호:시설명:좌표`이며 **Pleos POI ID가 아니다.** 파일에는 내비 POI ID가 없어 SDK POI 필드는 빈 값으로 전달한다.
- 자동 출처: `PLEOS_TBT_PUBLIC_REST_STOP_CATALOG`, 근거: `PUBLIC_CATALOG_DIRECTION_MATCH`.
- 공식 목록에서 사람이 방향 확인한 출처: `PLEOS_TBT_REVIEWED_PUBLIC_CATALOG`. 목적지·옵션·시설 순서/방향과 남은 TBT 경로가 같은 주기적 재탐색에서는 확인을 유지한다. 최초 확인 시각부터 24시간 유효하며 재탐색으로 연장하지 않는다. 상세 조건은 [E2E 수정](rest-stop-e2e-fix.md)을 참고한다.
- 실제/시험 이력에는 시설 종류·데이터 기준일·nativePoiAvailable을 구분해 남긴다. Room 스키마는 변경하지 않는다.
- 내비가 좌표·POI를 모두 생략하면, 목적지/옵션 보존과 동일한 전체 방향 이름의 새 항목을 두 번 안정적으로 재조회했을 때 `WAYPOINT_OBSERVED`로 기록한다. 항목 생성과 위치/식별 검증(`VERIFIED_WAYPOINT`)을 구분하며 공식 ID를 native POI처럼 사용하지 않는다.

## 검증과 한계

최종 표준 단위 테스트 531개 통과(앱 338, departure-core 149, departure-ui 44). 앱·계측 APK 빌드와 Release Kotlin 컴파일을 통과했다. 공식 데이터 로딩·실제 좌표 ETA 조회, 일반 앱의 도움 준비/중지·시설 조회, 내비 기록 조회의 선택 계측 3개를 에뮬레이터에서 실행해 통과했다.

합성 포트 테스트는 즐겨찾기 조회 없이 공식 파일 시설을 준비하는 경로, 휴게소보다 먼저 나온 졸음쉼터 선택, 동의 이후의 별도 적용, 제안 후 방향 변경 시 쓰기 차단, 모호한 방향 거부, 공식 목록에서의 수동 확인을 포함한다.

기기 조회 테스트에서 앱에 포함된 468개 자료를 읽고 용인휴게소 강릉 방향(37.245583, 127.2419801), 용인졸음쉼터 강릉 방향(37.28861576, 127.1387267)을 구분했다. 실제 SDK에서 **native POI 없이 휴게소 좌표로 ETA 1,798초**를 반환한 것을 확인했다. 이 조회는 경로를 변경하지 않았다.

이 결과는 좌표 기반 조회의 성공이며, CSV 시설을 실제 경유지로 추가하는 전체 기기 흐름의 성공을 대신하지 않는다. 좌표 기반 경유지 쓰기·재조회와 전체 음성 동의 흐름은 휴게시설이 포함된 실제 안내 경로에서 별도로 확인해야 한다. 현재 파일의 이름·제공 범위 밖 시설과 TBT 방향 정보 부족은 자동 선택 불가로 처리한다.
